# R-45 accessibility, responsiveness and reduced motion (a11y agent)

Target: WCAG 2.2 AA for everything outside the artwork itself. The artwork (what is drawn on the canvas) is the person's own work: its colours and text are theirs, and it is excluded from the contrast checks on purpose. Decisions: `D-1800` to `D-1809` in `docs/R45_DECISIONS.md`. Skills record: `docs/R45_SKILLS.md`. The older checklist in `docs/ACCESSIBILITY.md` is kept for reference; this file is the dated audit it said was missing.

Audit date: 2026-11-09, branch `feat/r45-a11y`.

## What this audit is, and is not

- **Is:** automated rules (axe-core 4.10.2, WCAG 2.0 to 2.2 A and AA plus best practice) in a real Chrome over every page and state; a real-keyboard walkthrough using real key events (not code reading); the browser's own accessibility tree; measured touch targets, overflow, contrast, motion and focus; fixes with regression tests.
- **Is not:** a real screen reader pass. No VoiceOver, NVDA, JAWS or TalkBack was driven (no driver is available to this agent). The accessibility tree that Chrome builds, which is what those tools read, was checked instead (`outline.mjs`: landmarks, headings, 0 unnamed controls), and what is announced was checked through the live regions. What a screen reader actually says, and how it feels to use, still needs a person with one. Real-device checks (a notched phone, the iOS keyboard, a Windows high contrast theme) are also not done; they were emulated or unit tested. See "Open" at the end.
- **Is not:** a conformance claim. It says what was tested, what failed, what was fixed and what remains.

## How to run it again

Dev server on 8490 (or `BASE=...`) and a build, then. Run nothing else against the server at the same time: `php artisan serve` handles one request at a time, and a concurrent script made 45 editor states time out in one run (they passed when rerun alone).

```
sh scripts/dev/a11y/run-all.sh            # everything, about 35 minutes (the sweep is 384 page states)
sh scripts/dev/a11y/run-all.sh quick      # without the sweep and the responsive run
node scripts/dev/a11y/sweep.mjs --only '^editor' --vp 390 --theme dark   # one slice
```

| Script (`scripts/dev/a11y/`) | What it does |
|---|---|
| `sweep.mjs`, `scenarios.mjs` | axe-core over every page and state, 3 widths x 2 themes. The page and state list lives in `scenarios.mjs`. Also records h1 count, duplicate ids and horizontal scroll. `--ci` exits 1 on a serious or critical violation. |
| `keyboard.mjs` | The editor with the keyboard only: skip link, tab walk (names, focus rings, no trap), Tab on the canvas, arrows, Alt+arrows, text editing in and out, Shift+F10 and the Menu key, zoom, the shortcut sheet, a dialog (focus trap and restore), the rail, Layers (arrows, F2, Alt+Up), the canvas list. 46 checks at 1440. |
| `responsive.mjs` | Every page at 320, 390, 768, 1024, 1440, 1920, phone landscape (844x390), 200% zoom (720 px), text-only 200% at 1440 and at 390: horizontal scroll, clipped content, targets under 44 px (24 px on desktop). |
| `focus-obscured.mjs` | Tabs through 12 pages at 390 and 1440 and checks the focused control is not hidden behind a fixed bar (WCAG 2.4.11). |
| `motion.mjs` | Under `prefers-reduced-motion`: nothing animates, transitions or loops on 11 pages. Without it: the editor never plays a design's animation on load; the Animate panel has play and pause. |
| `states.mjs` | Slow, failing (network) and 500 responses for the JSON a page or tab needs: a loading state, words and a retry button. |
| `labels.mjs` | Every visible field on 15 pages and every editor tab (Simple and Pro) has a real label, not only a placeholder or title: 37 surfaces, 0 unlabelled. |
| `contrast.mjs` | Token pairs in both themes against 4.5:1 (text) and 3:1 (controls, focus, selection). |
| `outline.mjs` | Landmarks, headings and unnamed controls from Chrome's accessibility tree. |
| `seed.mjs`, `render-errors.php` | Dev data (a flyer, a 4-page deck, a blank card, a brand kit, an asset, a comment, a version, a share link, and long-content data) and the six error views as files. |

Test counts: PHP 1,568 before this work, 1,601 after (32 page tests, 1 sanitiser test); JS 711 before, 721 after.

PHP regression tests: `tests/Feature/A11yPagesTest.php` (titles, one h1, main, skip link, language, no dashes, no list roles on links, errors tied to fields, error pages, legal pages) and `tests/Unit/DocumentSanitiserTest.php` (alt text). JS: `tests/js/a11y-keyboard.test.mjs` (resize step, control targets, the descriptions read aloud, the shortcut sheet, alt text, keyboard inset).

## After the polish merge (2026-11-10)

The four polish branches (editor shell, modules, pages, templates) were merged in and every check re-run on the merged build. Merged result: axe over 384 states: 0 errors and 366 states with 0 violations. The other 18 are one finding, on a tablet (768 px, editor with something selected): axe reports the drawer tab overlapping the "Close panel" button by 12 px (WCAG 2.5.8). It is reproducible only inside the sweep's sequence of states; a fresh load measured by hand shows no overlap (tab 70 px wide ending at the drawer edge, Close button inside the drawer), so it may be a transitional state of the drawer tab (`transition: right`), and it is listed here as open rather than fixed. Keyboard walkthrough 49 of 49 at 1440, 32 of 32 at 768 and 390. Responsive: 300 checks, 0 clipped, the only small targets are the 24 px page actions buttons. Focus obscured: 0 of 790. Motion, labels, states, contrast: pass. Test counts on the merge: PHP 1,669, JS 784.

`tests/e2e` on the merged branch: 01 (beginner) passes. 02, 03 and the desktop case of 11 fail exactly as they do on the trunk without this branch (the specs click the text of the new custom radio cards, whose hidden input intercepts the click; and a `.st-elsec--recent` section that stays hidden), so they are not regressions from this work.

### What was found and fixed

| Finding | Fix |
|---|---|
| Enter on a toolbar button started text editing instead of pressing the button while a text was selected; Delete, arrows and brackets reached the design from any focused control (WCAG 2.1.1, a real defect) | The canvas input ignores those keys when focus is on a control outside the canvas (D-1804) |
| No keyboard way to resize or open the context menu | Alt+arrows, Shift+F10, the Menu key (D-1803) |
| The canvas had no readable form; moves were silent | Canvas list and summary; moves announce where the element is now (D-1802) |
| Pictures had no alternative text | `alt` field, SVG `<title>` (D-1801) |
| Twelve pages titled only "Dot.Design" | Title follows the h1 (D-1805) |
| Editor had no h1; Jetstream sections were h3 under the h1 | Hidden h1; h2 (D-1805) |
| `aria-pressed` on links (critical), `role=list` on a form and links, `role=status` on a button | `aria-current`, plain groups, a live wrapper |
| Layers: a button inside a button (nested interactive); every eye and lock was a tab stop (60 on a 30 layer page) | Fold button moved out; roving tabindex (3 stops) |
| Two modules produced the same id `f-1` so a label pointed at another dialog's control | Separate prefix |
| The save chip had no name on tablets and phones (its text was `display: none`) | Visually hidden text instead |
| Brand preview svg without a name; scrollable list not focusable | Named, focusable region |
| Menus mounted outside every landmark; page strip was a `footer` | Inside `main`; a named `nav` |
| Rail tabs: every tab a tab stop | One stop, arrows, Home, End; closing a panel returns focus to its tab |
| Link in the share dialog distinguished by colour only | Underlined |
| Eye and lock buttons at 55% opacity under 3:1; hidden until hover so invisible on touch | Full colour; always visible on touch |
| Forced colours: controls drawn with `box-shadow` lost their edge, selected state vanished | `ds/a11y.css` (D-1806) |
| 40 px buttons, 20 px stand-alone links, 32 px pager | 44 px on touch and narrow screens; 24 px floor everywhere |
| Focus hidden behind the fixed tab bar on phones | `scroll-padding` |
| Notch and keyboard not handled on the phone workspace | Safe-area insets, `keyboard-inset.js` (D-1807) |
| Cookies table overflowed at 320; settings switch overflowed at 320 | Wrapping table; wrapping group |
| Em and en dashes in the three legal pages | Rewritten (D-1808) |
| Sanitiser warned on a NAN used as text (found by the fuzzer) | Treated as not text |

### Recorded, not fixed (moderate or minor, with reasons)

- `incomplete` axe results (471 across 384 runs) are contrast checks axe cannot decide because of a pseudo-element, a `<select>` chevron image or a stacked panel. The token pairs they use all pass `contrast.mjs`; they are listed in the sweep JSON, not hidden.
- The 24 px "Page N actions" button on page thumbnails (D-1809).
- The page strip and the template filter chips scroll sideways on a phone; a focused chip can be partly off screen until the browser has scrolled it in (measured at most about 1 s on the template chips). It is never entirely hidden (WCAG 2.4.11 minimum).
- A text-only zoom to 200% shows no clipping on any page in the responsive run; German-length labels were approximated by that (a doubled font size is a harsher test than 30 to 40 percent longer words), and by the long-content seed: a 70 character kit name, a 300 character guideline, an unbroken 60 character business name.

## Keyboard map of the editor (what exists, all verified in `keyboard.mjs`)

Skip link to the canvas; Tab walks the top bar, the rail (one stop, arrows move, Enter opens), the panel, the canvas (a stop of its own), the properties, the page strip. On the canvas: Tab and Shift+Tab select the next and previous element, arrows move by 1 (Shift 10), Alt+arrows resize by 1 (Shift 10), Enter edits text or opens a group, Escape leaves, Delete removes, `[` and `]` reorder, Shift+F10 or the Menu key opens the menu, `+` `-` Shift+1 Shift+0 zoom, PageUp and PageDown change page, `?` opens the sheet. In Layers: arrows, F2 rename, Alt+Up and Alt+Down reorder, Left and Right fold groups, Delete removes. Selection toolbar, the Design and Layers tabs, the export file types and the brief's radio groups: arrow keys move along them (the tabs and radios also choose). Page strip: Left and Right, and the actions button for move, duplicate, delete. Add from a panel: every item is a button (Enter). A dialog traps Tab (native modal), Escape closes it and focus returns to what opened it.

Everything reachable by pointer has a keyboard path or a documented equivalent, except free positioning of an element by dragging it to an exact spot (the nearest equivalent is arrows for small moves and the numeric fields in Pro for exact ones) and drawing a guide by dragging from a ruler (the Page section adds and removes guides by number).

## What an assistive technology is told

Landmarks (editor): banner with the one h1 (the design name), navigation "Add and manage", complementary "Panel", main (with the "Design contents" region and the canvas), complementary "Properties", navigation "Pages of this design", region "Notifications". Other pages: the app rail is a complementary labelled with the product, one navigation, one main with the one h1. Roles and states: icon buttons have names, toggles use `aria-pressed`, tabs use `aria-selected`, dialogs are native modal dialogs with a label, the Layers tree is a tree with levels, selection and expansion, progress uses `role=progressbar`, errors on forms are tied to fields with `aria-describedby` and `aria-invalid`. Live regions: a polite region for selection ("Group: On time delivery row"), for edits ("Undid move"), for a move or resize with the position, for the page preview ("Preview, page 2 of 3"); the save chip is a status; toasts are `status`, failures `alert`; the first-run tip is a note. 98 controls in the editor's accessibility tree, 0 without a name (61 on Templates, 0).

## Responsive

Checked at 320, 390, 768, 1024, 1440, 1920, phone landscape and the two zoom cases for every page above: no horizontal scroll and no clipped content. The editor is a three-column workspace from 60rem up; below it the panels become bottom sheets, the top bar folds into a More menu under 48rem, and a tablet at 768 gets the compact layout with the full rail along the bottom (the keyboard script's compact subset passes at 768 and 390). Safe-area insets: left, right, top and bottom on the workspace, bottom on the rail and sheets. The on-screen keyboard: the workspace ends above it and the edited text is panned into view (arithmetic unit tested; not testable in headless Chrome). Gestures: the stage owns its touch (`touch-action: none`); the page scroll is the page's; pinch and two-finger pan are the engine's and were not re-tested on a device.

## States

Every list and panel that loads data was audited for loading (skeleton or status), error (words and a retry button) and empty: Templates page and tab, Assets page, Uploads tab, Comments tab, History tab, the brief step, the brand preview. All have a loading state; all show words and "Try again" on a network failure and on a 500 (`states.mjs`; the editor tabs read the open panel). Empty states were checked with a brand new workspace (a second account with nothing in it): Home, Designs ("No designs yet" with two ways forward), Brand ("Give your business its own look"), Assets (a folder and tag sidebar and an upload zone), Review ("Nothing is waiting for you"), Brand updates ("Nothing to review"), Activity and Integrations all say what the page is for and what to do next, with 0 axe violations; the blank page in the editor says "This page is empty" with three ways forward. Success is a toast (`status`). Long content: names truncate with an ellipsis where a row is fixed and wrap where it is not; checked with the long-content seed. No em or en dashes remain in rendered pages (`A11yPagesTest` checks the signed-in pages, the public pages and the error pages; the legal pages are checked at the source).

## Known limitations (honest)

- No real screen reader pass (see the top). Expect rough edges in how a screen reader reads the Layers tree and the canvas list together; the list is a navigable alternative, not a spatial one.
- A person who cannot see the canvas can add, select, name, describe, reorder, restyle and move or resize elements (arrows, numeric fields), but cannot judge the composition by sight; there is no spoken layout critique. Freehand spatial editing for a screen reader only user is limited to the element list and the numeric inspector.
- Contrast of the artwork is the person's own; the editor does not warn when a text colour disappears into its background (D-713 in the editor notes).
- Touch gestures (pinch, two finger pan, long press) were emulated, not run on a device.
- Forced colours was checked with Chrome's emulation (screenshots of the editor and the Designs list: every control has an edge, the selected state is Highlight with its own text colour, the artwork keeps its colours), not on Windows High Contrast.
- Exported PDF does not carry the alt text; exported SVG does (`<title>`). A PDF produced by the browser's print path is untagged.
- The share viewer for people outside the workspace was swept and is keyboard operable; its comment pin placement needs a pointer or the "Point to a spot" button followed by a click.

## Open (needs a person or a device)

1. VoiceOver on macOS and iOS, NVDA on Windows, TalkBack on Android: one pass each over Start, the editor (select, edit text, add, move, export) and the share viewer.
2. A phone with a notch and the on-screen keyboard: type into a text element near the bottom of a design and confirm it stays visible.
3. Windows High Contrast and macOS Increase Contrast.
4. Move the 24 px page actions button to 44 px if the owner prefers a visible target to the long press.
