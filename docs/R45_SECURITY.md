# R-45 security review

Owner: the security agent (wave 3). Branch `feat/r45-security`. Decisions: `docs/R45_DECISIONS.md` D-1400..D-1417. Privacy record: `docs/R45_PRIVACY.md`.
Scope: the integrated product on the wave 1 + 2 branch point (1,417 PHP tests, 615 JS tests), reviewed as an attacker and as an auditor, with authority to fix. Every finding of severity medium or higher has a fix and a regression test; lows are fixed where the fix was a few lines and are otherwise listed.

Method in one paragraph: read the router, the policies, every controller that takes an id or a document, the sanitiser, the uploaders, the share surface, the integrations and the jobs; wrote tests that enumerate the live router (so a new route cannot ship unprotected); fuzzed the document gate; put hostile strings into every user-controlled field of a seeded workspace and rendered every page, panel, dialog and export in a real Chrome (own headless instance, own profile, closed afterwards) with the policy both enforced and bypassed, counting violations and counting which probe fired; ran `npm audit` and an OSV query for every locked Composer package.

## 2. The authorisation matrix (task 1)

`tests/Support/RouteCatalog.php` reads the live router and sorts every route into public (an explicit allowlist, each entry with its reason), vendor (Fortify, Jetstream, Livewire, Sanctum, framework) or ours. `tests/Support/SecurityWorld.php` builds a whole business (owner, admin, editor, reviewer, a design with a page, version, comment, review, share link, grant, picture, brand kit with a logo, team template, assistant proposal) with a sentinel string in every name, so any leak is a substring search. `RouteAuthorisationMatrixTest` (13 tests, about 540 route requests per run):

- a route nobody classified, or one of ours outside `auth:sanctum`, fails; so does a stale public-allowlist entry; the operator-only routes must be exactly the 14 expected;
- every route of ours: guest gets 401 (JSON) or a redirect to login, with no data in the body;
- every route that takes an id: a member of every role of another business gets exactly 404 (never 403), and nothing of the first business appears in the body; likewise a stranger with only a personal workspace;
- every nested pairing: my project with a child id of another business, and with a child id of a sibling project of mine (page, comment, review, share, version, grant, picture, kit asset): 404;
- every mutating project route as a Reviewer: exactly 403 (the single exceptions are comment, resolve, unresolve), and the project set is unchanged;
- a removed member loses every project route on the next request; a deleted project is 404 on every one of its routes even for its owner;
- no GET listing or page, read as business A (JSON and HTML), contains business B's sentinel and none is a 5xx.

`PayloadIdorTest` (8) covers ids that arrive in a body: a picture of another business in an element, a group, a background, a v1 save or a copy; kit link/apply/attach; creating a kit in someone else's workspace; starting a design from another business's template, kit or logo; saving someone else's design as a template; a reply to another project's thread; a page, mention, reviewer, grant, export page list, assistant page or upload project of another business; another person's assistant proposal (even a colleague's); and signed share-picture URLs forged across tokens and designs.

## 3. Documents, AI, uploads, share links, headers

**Documents and AI as untrusted input.** `DocumentSanitiser` is a whitelist: it rebuilds each element from known keys, clamps every number, accepts only hex colours, known font keys, enumerated values and asset ids the saver may place, and re-serialises path data from tokens (only M L H V C S Q T Z with the right argument counts). `DocumentSanitiserFuzzTest` (7) throws 600 seeded poisoned pages (NaN, infinity, 1e999, control characters, bad UTF-8, `__proto__`/`constructor`/`prototype` at every depth, script and `javascript:`/`data:` strings in every field, path injection, over-size, over-depth, 300 maximum-size texts) at the strict and the lenient path and asserts the output: only keys the schema defines, finite bounded numbers, hex colours, clean path data, font keys, no control characters, and never an exception other than a plain refusal. `HostileRequestBodyTest` (4) sends malformed, truncated, 5,000-deep, NaN-literal, wrong-type and oversize bodies to the save, copy, proposal, brand and comment endpoints: 4xx, no trace, no path, the page untouched. The assistant's output passes the same gate (its own `OpValidator`, delimited data blocks, no delete or text-edit operation; reviewed in `docs/R45_AI.md` and not changed). Hostile text in a document is kept as text on purpose (it is the user's content) and is inert at every sink, below.

**Rendering (real browser).** Probe strings (`"><img src=x onerror=__x('ID')>`, `</text><svg onload=...>`, `<script>...`) were planted in: the design name, page name, element name and text, version label, comment bodies (member and guest), the guest name, review note, brand kit name, colour name, tagline, guidelines, voice words, contacts and logo label, the team template name, description and text, the picture name, folder and tag, the assistant proposal prompt and label, activity entries, the workspace name, a member's name. Every page and panel that shows them was opened as the owner and as the named reviewer: dashboard, start, brief, projects, the editor with every left tab (templates, elements, text, uploads, brand, comments, animate, background, history, assistant), the share, review, other sizes, download and keyboard-shortcut dialogs, preview, Pro mode, templates (including the team tab and a template's detail), brand list and editor, assets (selected), review inbox, activity, settings, integrations, profile, team, design-system pages, policy pages, 404, the public share viewer and its unavailable page; plus 12 URLs whose query strings and hash carry probes. The same pass was run twice: CSP bypassed (so an escaping bug would execute) and CSP enforced. Result: all probes visible as text on the pages that show them (positive control, 30+ markers seen), **none executed in either run**, no injected element or attribute. SVG, PNG, JPG and PDF exports were prepared from the hostile design: the SVG parses as XML with zero script elements and zero handlers, the hostile text is element text, and the PNG is byte-identical with the policy enforced and bypassed.

**Uploads.** JPG, PNG and WebP only, type from the bytes (never extension or client MIME), SVG refused outright (not sanitised: stated), header dimensions checked before decoding (8,000 px a side, 40 MP, memory guard), every image decoded and re-encoded (EXIF/GPS, comment segments and appended data gone; verified with a PHP payload in a JPEG COM segment and a PNG tEXt chunk), file names never reach the path (`{user}/{40 random}.{ext}`; ten hostile names tried), 8 MB limit, per-user quota taken under a row lock (so two uploads cannot both slip under it), 20 uploads a minute per person. Serving is only through policy-checked routes with `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, `Cross-Origin-Resource-Policy: same-origin`, `Content-Disposition: inline`, `Cache-Control: private`, `Vary: Cookie`; a row whose path or type is dangerous is never streamed; the `/storage` routes are off. Thumbnails: PNG/WebP only, 300 KB, 1,600 px, re-encoded, same headers. Dot.Files: acknowledge flag, format allowlist, scope pattern, 25 MB, bytes must match the format, SVG must be inert (S-2). `UploadAbuseTest` (9).

**Share links.** 40 random alphanumerics, SHA-256 stored (never the token; the owner's list, the audit trail and the data download never carry it), `hash_equals` on the hash, then expiry and revocation; malformed, unknown, expired, revoked and deleted-design links render the identical 404 page; unknown, revoked and expired do the same work (one query each, asserted; a malformed token is refused before the database, which only tells a visitor the shape every valid link already has). No session, no cookie (checked in the browser: zero cookies after view and after commenting), `X-Robots-Tag: noindex`, `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`. Guest comments: honeypot (answered like success, stored nowhere, not counted), 60/2,000 characters, control characters stripped, only a display name and no address stored (no column anywhere could hold one: asserted), a visitor cannot set user, share, project, parent, mentions or resolution, per-link-and-visitor throttle (6 a minute), the new per-link daily ceiling and miss counter (S-6). Pictures are signed 10-minute URLs that die with the signature, the link and the design. The comment POST is CSRF-exempt because the page has no session; exemptions are pinned to exactly three routes (`CsrfAndSessionTest`).

**Headers and CSP (task 5).** `SecurityHeaders` runs on every response and builds the policy around a fresh nonce (`Vite::useCspNonce`, which Livewire's own tags also use):

```
default-src 'self'; script-src 'self' 'nonce-...' ['unsafe-eval' only when Livewire's bundle is on the page];
style-src 'self' ['unsafe-inline' only on Livewire pages]; style-src-attr 'unsafe-inline';
img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; media-src 'self' blob:; worker-src 'self' blob:; manifest-src 'self';
frame-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; report-uri /csp-report
```

plus `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, a Permissions-Policy that turns off camera, microphone, geolocation, payment, usb, bluetooth, serial, hid, midi, display-capture and sensors, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS on HTTPS (180 days, no includeSubDomains or preload: sibling Dot platforms set their own), `X-Robots-Tag: noindex` for signed-in pages, `X-Powered-By` removed. The editor, the share viewer, the welcome and policy pages and every page without Livewire never get `unsafe-eval`; the signed-in shell does, because Jetstream's flash banner and menus use Alpine expressions (it evaluates them with `new Function`). The scripts still need the nonce, there is no inline script in any view (asserted), no external host in any directive or any resource (asserted), and no inline event handler (asserted). Rather than keeping the Jetstream pages report-only, all pages are enforced: the render sweep found no violation anywhere (section 4), and `SECURITY_CSP_REPORT_ONLY=true` is the one-line fallback. `/csp-report` stays public, session-less, throttled and stores only the directive and the blocked host.

CSRF: the framework skips its check under test, so `EnforcedCsrf` removes that shortcut; every non-GET web route (JSON included, 70+) answers a forged request with 419 except the three pinned exemptions; a valid token passes; a wrong one fails. Cookies: session HttpOnly, SameSite Lax, host-only, Secure under https (S-8); XSRF cookie SameSite Lax. Session id changes at login; logout ends the session.

Rate limits are per person when there is one (`design-saves`, `-shares`, `-comments`, `-thumbnails`, `-exports`, `-uploads`, `-ai`, `-briefs`, and the generic `throttle:N,1` which keys on the user id): asserted by building each limiter's key for two users on one address, and by a behavioural test (same person from a second address shares the budget; a colleague on the same address does not). Defined in providers, never in route files (route:cache).

## 5. Dependencies and secrets (task 7)

- **Composer:** 140 locked packages. `composer audit` could not reach packagist.org from this machine (timeout), so the same question was put to OSV (osv.dev, ecosystem Packagist) for every locked package and version: **0 advisories** (control: laravel/framework 8.0.0 returns 12, so the query works). CI should still run `composer audit`.
- **npm:** 9 advisories before, 2 after `npm audit fix` (lockfile only; `package.json` unchanged). Remaining: `postcss-selector-parser` < 6.1.5 (moderate, quadratic parsing of a hostile CSS selector) via `@tailwindcss/typography`, a dev dependency whose offered "fix" is a downgrade to 0.5.4. It is exercised only at build time on this repo's own CSS; not forced. All packages in the lockfile are dev dependencies: there is no Node at runtime and nothing built from them runs with the advisories' preconditions.
- **Secrets:** a scan of every tracked file (1,150) for API-key, token, private-key and JWT shapes and for assigned secrets found none; `.env` is untracked, `.env.example` carries no secret and no real key (its unsafe defaults were fixed, S-8); the built assets contain no secret. Secrets are read from configuration only, are never returned by any integrations page (asserted with every secret set) and never reach a log line (the webhook refusal line is asserted to hold none).
- **Errors:** with debug off, an exception, a database error, a 403, a 404, a forged form and a throttled request answer a plain page or plain JSON: no SQL, path, class name or trace (`ErrorLeakTest`, 5). The deploy forces `APP_DEBUG=false`.
- **Background jobs:** the Notify listener and the Analytics job queue ids and aggregate counts, not addresses or secrets (the planner resolves recipients when the job runs and re-checks membership then); retries are idempotent (idempotency keys at Notify, a day-stamped snapshot at Analytics).

## 6. Reviewed and found sound

- Route-model binding through global scopes (a row you cannot see is a 404 with the same body as a missing id), policies as a second layer, roles read from the database on every check (a removal or demotion bites on the next request), the 404 body that never names a model.
- Tenancy by `team_id` on every row plus scopes and policies; no `withoutGlobalScopes()` in any controller that serves a person (the uses are in services that scope by project or token explicitly).
- Compare-and-swap saves; asset ownership resolved in one batch per save; `ProjectAssets` (own, already in the project, filed under it, or a workspace brand asset).
- Template instantiation drops pictures from saved templates and checks every logo and photo with `AssetAccess`; the brand kit summary sent to the model leaves out contacts and website.
- InfoDot sign-in: token in a POST body, Origin check against InfoDot's host, spent after use, session regenerated, redirect sanitised.
- Webhook: HMAC over timestamp and body, constant-time compare, five-minute window, identical 401 for every refusal.
- Integrations: URLs only from configuration, timeouts and a circuit breaker, no secret in a log or a page.
- Client: no `innerHTML` with data (the one use sets static icon markup from a fixed set), no `eval`, clipboard paste is size-capped, parsed as data and run through the schema normaliser, `files.js` accepts only http(s) URLs.
- Share page embeds its document as a JSON script block with `JSON_HEX_TAG|AMP|APOS|QUOT`, and a server-drawn SVG whose every value is escaped or cast.

## 7. Residual risks and things for the owner

1. **`unsafe-eval` remains on the signed-in Jetstream shell.** It is needed for Livewire's bundled Alpine; it is not on the editor, the share viewer, the public pages or any page without Livewire (asserted). The way out is removing the Alpine expressions from Jetstream's banner and menus, or Livewire's CSP build when available.
2. **Production `.env` must be checked at deploy.** The old `.env.example` said `SECURITY_CSP_REPORT_ONLY=true` and `APP_URL=http://...`: a host `.env` copied from it keeps CSP report-only and the session cookie non-Secure. Required there: `SECURITY_CSP_REPORT_ONLY` unset or false, `APP_URL` https (or `SESSION_SECURE_COOKIE=true`). The deploy agent has this note.
3. **Client address and proxies.** The app has no trusted-proxy setting; the address used by every limiter is the connection's. Directly on the shared host that is the client; if a CDN or reverse proxy is ever put in front, configure `trustProxies` or every visitor shares one bucket.
4. **Sessions** are stored in the database with the address and browser agent (Jetstream's "browser sessions" needs them) and the payload is not encrypted (`SESSION_ENCRYPT=false`, which also keeps the password-hash check value readable to anyone who can read the table). See the privacy record. Setting `SESSION_ENCRYPT=true` is safe and signs everyone out once.
5. **Timing.** Equal work for every not-found is asserted structurally (query counts); no wall-clock measurement was made, because a test machine cannot resolve a difference this small.
6. **A share link is a bearer credential.** Anyone with it sees what it shows; "download allowed" is a viewer-side flag (the page already holds the document, so the server cannot enforce it) and is described that way. The signed picture URL can be forwarded for ten minutes.
7. **Row-level database isolation** does not exist (no PostgreSQL row security): isolation is application-level (scopes, policies, tests). The matrix test is the guard rail.
8. **AI:** the real Anthropic API was never called (no key, per the assistant's own record); the request shape and the privacy statement rest on code reading.
9. **Crash-recovery journal** (unsaved pages) lives in the browser's localStorage up to 30 days and survives logout on that browser; the cookie policy now says so.
10. **Not verified:** Firefox and Safari behaviour of the policy (Chrome only); the production host's web-server limits (`client_max_body_size` etc., see `docs/R45_BACKEND.md` section 9).
