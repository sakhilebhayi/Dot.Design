## editor-ui (wave 2): what was really used

| Skill | Status | How it was used |
|---|---|---|
| `impeccable` | available, invoked | `impeccable context --target resources/js/studio` ran (no PRODUCT.md; DESIGN.md "The Light Table" is the incumbent visual system, and the owner's brief fixes the direction, so no init interview). Mode: **Operate** (an editor is a tool people work in): familiar patterns over expression, one family of controls, state-rich components (hover, focus, pressed, disabled, busy, error, empty, loading skeletons), 150 to 250 ms motion that only conveys state, no orchestrated entrance, overlays that escape their container (popovers and sheets are `position: fixed`). The craft floor was applied: no eyebrows, no gradient text, no side-stripe borders, no hero metrics, no modal where a panel works (the only modals are confirm, recovery, conflict and the registered module dialogs), selection and caret and scrollbars themed from the tokens, tabular numerals in every numeric field. `impeccable detect` was run on `studio.css`, the layout, the page view and `resources/js/studio/ui`: 0 anti-patterns; advisories were the canvas grid (a real measurement surface, so kept) and off-ramp specimen sizes (font specimens must show a size, kept). |
| `design-taste-frontend` | available, invoked | Read `references/app-screens.md` (builders and editors are in its scope) and used it for the workspace: colour on selection and data only (the cyan hue is selection, focus and progress; the page itself brings all the colour), flat surfaces separated by tone steps and 1px rules, navigation that recedes (the rail's selected tab is a paper chip, not a coloured pill), one primary action per context, honest empty states ("This page is empty", "No pictures yet", "No brand kit yet") that offer the next step, words of the trade (Fill the space, Move the picture inside its frame, Spread evenly) instead of generic nouns, a first screen that shows the product (the page) rather than chrome. Its page run (draw and inspect scripts) was not used: the brief and DESIGN.md fix the direction, which is the skill's own rule. |
| `gsap-core` | not used | No timeline motion was needed: every transition is a 120 to 320 ms CSS transition behind `prefers-reduced-motion`. |
| `hallmark`, `design-md`, `awesome-design-md`, `open-design` | not used | They are for new public pages, design-token files and brand specs; DESIGN.md already exists (ds agent) and was read, not changed. |
| `ui-ux-pro-max`, `emil-design-eng` | UNAVAILABLE | Still dangling symlinks (see above). Not used and not claimed. |

Verification tools actually run for editor-ui: `impeccable detect` (source tier, see above), automated scans in the real browser (every button, link, input and select in all six tabs in both modes has an accessible name: 0 unnamed; horizontal overflow check at 390, 768 and 1440), the contrast of every token pair comes from DESIGN.md (not re-measured), and the browser acceptance in `docs/R45_UI_EDITOR.md`.
