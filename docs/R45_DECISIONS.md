# R-45 decisions log

Append-only. Format: `D-n (agent, date): decision. Why.` On merge conflicts keep both sides.

D-1 (coordinator, 2026-11-09): Workspace tenancy = Jetstream Team; projects stay private to the owner by default, `visibility=team` shares with the workspace. Why: matches InfoDot team sync and the brief's business-workspace model without breaking existing owner-only rows.
D-2 (coordinator, 2026-11-09): Editor is vanilla ES modules built by Vite with ONE SVG renderer for screen and export. Why: export parity, no Alpine/Livewire start-order coupling, testable pure modules.
D-3 (coordinator, 2026-11-09): Document schema lives in resources/design/document-schema.json, read by PHP and JS. Why: one source of truth, no drift.
D-4 (coordinator, 2026-11-09): No real-time co-editing, background removal, social publishing, stock photos or MP4 export; each is stated in the report as not built. Why: no honest implementation is possible on the shared host / without licences or APIs.
D-500 (library, 2026-11-09): The schema's `bind_key` pattern is `^[a-z][a-z0-9_]{0,39}$` (coordinator change, applied in this branch and in `TemplateSchemaValidator`). Why: `photo_1` to `photo_3` are required slot keys and the old pattern rejected digits.
D-501 (library, 2026-11-09): The library index is `database/templates/_index.php`, not `index.php`. Why: `design:seed-templates` loads every top-level `database/templates/*.php` except names starting with `_` or an upper-case letter, so a plain `index.php` would be read as a definition.
D-502 (library, 2026-11-09): Template files use only the business catalogue vocabulary (kinds, categories, purposes, objectives, industries, styles) and `Template::start` throws otherwise; seven library kinds the catalogue lacks (`logo`, `brand-guidelines`, `company-profile`, `product-catalogue`, `service-catalogue`, `quotation`, `packaging`) are allowed as extras and listed for the coordinator to add to `config/design_copy.php`. Why: the brief asks for those kinds, and inventing an unlisted kind silently would break labels and filters.
D-503 (library, 2026-11-09): Per-character advance widths of the 18 allowed fonts (measured with canvas measureText at weights 400, 700, 900) live in `database/templates/Support/font-advances.json` and size and test every text box with 15% spare width. Why: the first estimator used per-font averages and under-measured short heavy words by up to 25%; real advances caught every collision the contact sheet later confirmed.
D-504 (library, 2026-11-09): Templates enforce each format's own safe zone (from `config/design_formats.php`, mirrored in `Support/Formats.php`), not only a 4% margin. Why: story, TikTok, cover and roll-up formats hide large areas behind app UI or the stand base.
D-505 (library, 2026-11-09): Brand tokens are generated by the DSL from a palette-to-role map (`Palette::$tokens`); a brand-driven page colour adds a full-page "Background colour" shape because only elements carry tokens. Why: one rule keeps all 58 templates consistent and lets the instantiator recolour a design without guessing.
D-506 (library, 2026-11-09): Logos and packaging are shipped as honest starting points (type and simple shapes; front panel concept, not a dieline) and said so in their descriptions. Why: the honesty rules forbid presenting a layout as a finished brand mark or a press-ready dieline.
D-507 (library, 2026-11-09): The dev contact sheet loads Google Fonts for approximating wrapping and is deleted from `public/` before commit; product code never references an external host. Why: owner rule on no CDN at runtime.
